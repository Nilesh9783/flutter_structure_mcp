# MEM-001: StreamSubscription Memory Leak

## Rule
Always cancel active `StreamSubscription` instances when the enclosing StatefulWidget, Controller, or View Model is disposed.

## Description
When you call `stream.listen(...)`, a listener callback is registered. If the subscription is not explicitly cancelled, the stream publisher retains a reference to the listener closure, preventing the garbage collector from reclaiming the listener's scope.

## Why It Matters
Failing to cancel subscriptions leads to memory leaks, causing the application to consume more RAM over time, slow down, and eventually get terminated by the OS due to Out-Of-Memory (OOM) errors.

## Bad Example
```dart
class _MyState extends State<MyWidget> {
  @override
  void initState() {
    super.initState();
    myStream.listen((data) {
      setState(() {});
    });
  }
}
```

## Good Example
```dart
class _MyState extends State<MyWidget> {
  late StreamSubscription _subscription;

  @override
  void initState() {
    super.initState();
    _subscription = myStream.listen((data) {
      setState(() {});
    });
  }

  @override
  void dispose() {
    _subscription.cancel();
    super.dispose();
  }
}
```

## Recommended Fix
Save references to all subscriptions created with `.listen()` and invoke `.cancel()` inside `dispose()` for Widgets, or `onClose()` for GetxControllers.

## Severity Guidance
- Medium: Potential memory leaks that trigger only during screen transitions.
