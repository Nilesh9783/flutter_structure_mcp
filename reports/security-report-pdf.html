3. High-Priority Performance Flaws: Controller in build()

Instantiating controllers inside build() forces memory re-allocations on every frame render, causing UI stutter, dropped text inputs, and lost scroll states.

Component / Area File Path Line Issue Description
Performance Engine lib/performance/performance_engine.dart 100 Use of Static ListView Instead of Lazy ListView.builder
App Text Form Field templates/shared/common/reusable_component/widgets/app_text_form_field.dart 38 Controller Instantiation Inside Widget build() Method
Dropdown Overlay templates/shared/common/reusable_component/widgets/custom_dropdown/dropdown_overlay/dropdown_overlay.dart 109 Controller Instantiation Inside Widget build() Method
Items List templates/shared/common/reusable_component/widgets/custom_dropdown/dropdown_overlay/widgets/items_list.dart 25 Controller Instantiation Inside Widget build() Method
Common Transaction List templates/shared/common/reusable_component/widgets/trasaction_lists/common_transaction_list.dart 69 Controller Instantiation Inside Widget build() Method
Standard Fix Architecture:
class _SafeInputWidgetState extends State<SafeInputWidget> {
  late final TextEditingController _controller;

  @override
  void initState() {
    super.initState();
    _controller = TextEditingController(); // Allocated once
  }

  @override
  void dispose() {
    _controller.dispose(); // Safely freed from memory
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => TextField(controller: _controller);
}
